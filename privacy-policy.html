6. Retention

App state is partly stored locally using a persistence mechanism (Zustand + AsyncStorage), including YouTube-related cache and preferences under keys video-storage-{user identifier}-{opaque suffix}.

  • Firebase Authentication account data: retained until you delete the account in the App. Logging out does not automatically delete your user record on Firebase. Erasure is available only through Account → Delete account in the App. Once your Firebase Authentication user record is deleted through that in-app flow, Cloud Functions delete linked Firestore documents for your UID (including users and userFetchLimits).
  • Local copy of YouTube data (video-storage record): may remain on the device after log-out. To permanently remove the local copy: uninstall the App or clear App data in Android settings.
  • Advertising data: per Google AdMob retention policies.
  • Google Analytics for Firebase (GA4) event data: retained per Google's configurable retention settings (e.g. 2 or 14 months). The Developer does not maintain a separate copy of raw analytics logs outside Google's services.
  • Firebase Crashlytics crash and stability data: retained on Google's servers (typically around 90 days for non-fatal events).
  • Other data held locally: same rules as for the video-storage record unless you clear app data or uninstall.

Deletion of account data starts as soon as you confirm the action: the Authentication user is removed and Cloud Functions clean linked Firestore rows, subject to propagation and backup delays on Google's systems.

11. Security

The Controller applies appropriate technical measures to protect personal data, including:

  • Encrypted communication (HTTPS/TLS) with Google services;
  • OAuth tokens stored with platform-secure mechanisms on Android (OS-backed secure store), without trusted legacy fallback to plain AsyncStorage.
  • Authentication via Firebase Authentication;
  • Firebase App Check — integrity verification for protected Firebase backends;
  • Firestore security rules limiting write access to user-specific data; the YouTube Charts cache is configured for public read only.
  • Token-storage hardening: OAuth token reads on native fail closed when secure storage is unavailable.
  • Security telemetry minimisation: abuse-prevention events are logged in pseudonymous, low-cardinality form, without collecting payment card data or free-text user input.
  • Server-side abuse controls: selected backend endpoints apply transactional rate-limits and lightweight suspicious-activity scoring.
  • Reward and ad abuse controls: rewarded-ad grants are bound to short-lived backend-issued nonces; local ad-free state is treated as cache only.
